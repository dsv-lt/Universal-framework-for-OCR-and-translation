# Руководство по переводу: Pivot через EN, Glossary RAG, `grammar.md` и Conlang Text LoRA

В `im_Translator` перевод устроен по схеме **двухступенчатого пивота**:

```text
[Source / Postprocessed] ──(Шаг 1 + GlossaryRAG + grammar.md)──► [EN] ──(Шаг 2, если Target != EN)──► [Target (RU/JP/...)]
```

## Почему пивот через английский (`pivot_via_en: true`)?
1. У большинства открытых моделей (особенно компактных 3B–14B) английские семантические представления самые сильные.
2. Почти все грамматики, фанатские вики и словари вымышленных языков написаны на английском — не нужно переводить весь глоссарий на русский, немецкий или японский.
3. Если целевой язык пользователя и есть `en`, второй шаг пропускается автоматически.

---

## Когда использовать RAG + `grammar.md`, а когда Text LoRA?

| Размер данных / ситуация | Рекомендуемый режим | Почему |
| :--- | :--- | :--- |
| **Есть только словарь + описание грамматики (0–300 параллельных фраз)** | **RAG (`glossary.json`) + `grammar.md`** *(без обучения)* | Работает мгновенно на любой LLM (`llama.cpp`, `Ollama`, API). Модель опирается на подставленные статьи словаря и грамматические правила прямо в системном промпте. |
| **300–1 000 параллельных предложений** | **RAG + `grammar.md` с 5–15 few-shot примерами** | Few-shot примеры в `grammar.md` дают прирост качества без риска переобучить маленькую LoRA и сломать инструкции модели. |
| **1 000+ качественных параллельных пар `Source → EN`** (сложная непривычная морфология, полисинтетические языки, агглютинация, которую промпт не тянет) | **Conlang Text LoRA + RAG сверху** | Текстовая LoRA учит модель устойчиво разбирать грамматику и аффиксы языка, а **RAG поверх LoRA** продолжает страховать редкие термины и имена собственные. |

## Шаг 1. Заполнение `glossary.json` (для RAG)

Шаблон: [`docs/templates/glossary.template.json`](templates/glossary.template.json).

Формат — JSON-массив объектов (допускается также объект `{"entries": [...]}`):

```json
[
  {
    "term": "Rudeus",
    "en": "Rudeus",
    "pos": "proper_noun",
    "variants": ["Rudeusen", "Rudeusi"],
    "is_proper_noun": true,
    "notes": "Main protagonist name; DO NOT translate or replace with a common word."
  },
  {
    "term": "ur",
    "en": "water",
    "pos": "noun",
    "variants": ["ura", "urak", "uretik"],
    "is_proper_noun": false,
    "notes": "Basque root for water; common in Water-god magic spells."
  }
]
```

### Как работает `GlossaryRAG`
1. Берёт входной текст и токенизирует его (без учёта регистра).
2. Ищет совпадения по:
   - точному полю `term`,
   - списку словоформ `variants`,
   - общему началу слова (префикс/основа ≥ 4 символов, полезно для агглютинативных языков вроде баскского или квенья).
3. Подмешивает в системный промпт **только найденные релевантные статьи** (ограничивая `top_k`), чтобы не раздувать контекст и не сбивать LLM лишними словами.
4. Для записей с `"is_proper_noun": true` добавляет жёсткое правило: **не переводить и не «исправлять» имя**.

## Шаг 2. Заполнение `grammar.md` (системная памятка)

Шаблон: [`docs/templates/grammar.template.md`](templates/grammar.template.md).

Рекомендуемая структура памятки (старайтесь держать её компактной — **300–800 токенов**):
1. **Краткий профиль языка:** порядок слов (`SOV`, `SVO`, `VSO`), тип морфологии (агглютинативный, флективный, изолирующий).
2. **Таблица ключевых аффиксов / частиц:** падежи, множественное число, время глагола, отрицание.
3. **Особые правила:** числа, знаки препинания, лакуны `[?]` или зачёркивания `~~text~~`.
4. **5–10 эталонных пар `Source → EN` (few-shot):** именно примеры предложений сильнее всего выравнивают стиль и грамматический разбор LLM.

## Шаг 3. Подготовка датасета для опциональной Text LoRA (`conlang_lora.jsonl`)

Шаблон: [`docs/templates/conlang_lora.template.jsonl`](templates/conlang_lora.template.jsonl).

Каждая строка файла — отдельный JSON-объект (формат JSON Lines):

```json
{"source": "Urak mugitzen dira.", "en": "The waters are moving.", "glossary_hits": ["ur"], "notes": "Absolutive plural -ak; present continuous -tzen dira"}
```

### Практические советы для Text LoRA
- **Таргет обучения всегда `EN`** (`source → en`), чтобы не дробить маленький корпус на несколько языков перевода.
- Сохраняйте системный формат обучения таким же, как при инференсе (с блоком `Grammar` и `Glossary`), чтобы после обучения модель продолжала слушаться обновляемого словаря `glossary.json`.
- Для 12 ГБ VRAM (например, RTX 5070) оптимальна QLoRA 4-bit на базе `Qwen2.5-7B-Instruct` / `Qwen3-8B` / `Gemma-3-4B` (ранг `r=16` или `r=32`, `learning_rate=1e-4`–`2e-4`, 2–3 эпохи с контролем валидационного `loss`).
- После проверки конфигурации можно сформировать команду обучения в CLI или на вкладке **Synth & Train** в Web UI.
